# Журнал изменений

Одно место, в котором видно, что изменилось в telecli: что добавили, что исправили,
что стало работать иначе. Формат — [Keep a Changelog
1.1.0](https://keepachangelog.com/ru/1.1.0/), номера версий — по [SemVer](https://semver.org/lang/ru/):
`vMAJOR.MINOR.PATCH`. Свежие разделы сверху, каждый номер версии — тег в git.

## Правило файла

Задача, которая меняет то, что человек видит или делает, добавляет строку в раздел
«Не выпущено» в том же PR, где изменение. Строка пишется простыми словами для
человека и в ней есть ссылка на задачу или PR; заголовок коммита в журнал не
копируется. Всё, что человек не заметит — тесты, CI, внутренние заметки и решения, —
в журнал не попадает.

Выпуск версии: раздел «Не выпущено» получает номер и дату, ставится тег с этим
номером, а сборка получает номер вместо `dev` через `-ldflags`. Команда —
`scripts/release_version.sh`, она же проверяет, что выпускать есть что.

## Не выпущено

### Добавлено

- Журнал изменений `CHANGELOG.md` в корне: что добавлено и что исправлено в каждой
  версии, по одному файлу вместо чтения коммитов и задач.
  [#71](https://github.com/naghuale/tele/issues/71)
- Поиск по чатам: `/` в списке чатов открывает строку поиска, список сужается по
  мере набора, стрелки ходят по совпадениям, `Enter` открывает чат, `Esc` закрывает
  поиск и возвращает курсор на прежний чат.
  [#47](https://github.com/naghuale/tele/pull/47)
- Меню действий над сообщением по `a`: скопировать текст, отменить сообщение,
  создать новое сообщение вместо неудачного, закрыть.
  [#46](https://github.com/naghuale/tele/pull/46)
- Решение при сообщении с неопределённым результатом: по умолчанию запись остаётся
  как есть, а новое сообщение создаётся только по явному решению человека — так
  повторная отправка не создаёт дубликат.
  [#46](https://github.com/naghuale/tele/pull/46)
- Присутствие собеседника в заголовке разговора: `Online`, `Connected` или когда он
  был в сети.
  [#45](https://github.com/naghuale/tele/pull/45)
- Строка состояния под заголовком: соединение (`Connected`, `Connecting…`,
  `Updating…`, `Waiting for network`, `Connecting to proxy…`), счётчики очереди
  (`N queued`, `N retrying`) и восстановление прерванных сообщений.
  [#40](https://github.com/naghuale/tele/pull/40)
- Пустые состояния и ограниченное ожидание: список чатов не «висит» молча, а говорит,
  что идёт загрузка, и ждёт столько, сколько может.
  [#40](https://github.com/naghuale/tele/pull/40)
- Отправленные сообщения видны в ленте вместе с состоянием доставки: `● Queued`,
  `◐ Sending`, `↻ Retrying at 14:35`, `✓ Sent`, `! Failed`, `? Delivery uncertain`,
  `⊘ Canceled`; у неопределённого результата — предупреждение «Message may already
  have been sent».
  [#36](https://github.com/naghuale/tele/pull/36)
- Многострочный ввод: курсор ходит по черновику, работают `Backspace`, `Delete`,
  `Home`/`End`, `Ctrl+A`/`Ctrl+E`, `Ctrl+U`, `Ctrl+W`, `Ctrl+K`, строка переносится
  по ширине поля и растёт до четырёх строк, `Alt+Enter` — новая строка, `Enter` —
  отправить.
  [#34](https://github.com/naghuale/tele/pull/34)
- Список чатов обновляется сам по событиям Telegram: новый чат, новое название,
  новое сообщение и прочитанное не теряются и не ждут перезапуска.
  [#16](https://github.com/naghuale/tele/pull/16)
- События сообщений в открытом чате приходят в ленту сразу: обновлённое,
  заменённое, неудачное и удалённое сообщение не ждут перезагрузки истории.
  [#27](https://github.com/naghuale/tele/pull/27)
- Листается история вверх: на самом старом загруженном сообщении подгружается
  следующая страница, конец истории — страница без новых сообщений.
  [#12](https://github.com/naghuale/tele/pull/12)
- Команда `telecli outbox reset`: начинает новую пустую очередь, когда ключа старой
  очереди достоверно нет; старая очередь не удаляется, а остаётся рядом как
  `orphaned` с заметкой.
  [#24](https://github.com/naghuale/tele/pull/24)
- При настройке проверяется форма API hash — 32 шестнадцатеричных символа, само
  значение не выводится: опечатка находится на настройке, а не в ответе Telegram.
  [#8](https://github.com/naghuale/tele/pull/8)
- Страница справки «Sending paused»: что означает приостановленная отправка и что
  делать по каждой причине.
  [#18](https://github.com/naghuale/tele/pull/18)
- Три тёмные темы оформления: `catppuccin-mocha` (по умолчанию), `gruvbox-dark`,
  `tokyo-night-storm`; выбираются в секции `[tui]`.
  [#28](https://github.com/naghuale/tele/pull/28)

### Изменено

- Отправка всегда идёт через зашифрованную очередь (`durable`): прямой отправки
  больше нет. Конфигурация со старым `mode = "direct"` читается как `durable` с
  предупреждением, а `--mode direct` отклоняется с объяснением, а не игнорируется.
  [#20](https://github.com/naghuale/tele/pull/20)
- Если очередь не открывается, программа всё равно запускается: список чатов и ввод
  работают, отправка приостановлена с текстом причины на экране, подробности — в
  `telecli doctor`.
  [#20](https://github.com/naghuale/tele/pull/20)
- Оформление приведено к утверждённому макету: фокус панели — одна акцентная линия
  под её заголовком, имя чата жирное со временем справа, метка непрочитанного справа,
  сообщения без рамок и пузырей.
  [#52](https://github.com/naghuale/tele/pull/52)
- Интерфейс — две панели без рамок, фокус переходит по `Tab` по кругу, `Esc`
  возвращает фокус назад (из ввода — в ленту, из ленты — в список чатов) и никогда
  не завершает программу; выход — `q` из списка чатов и `Ctrl+C` откуда угодно.
  [#30](https://github.com/naghuale/tele/pull/30)
- Строка подсказок называет только те клавиши, которые работают в текущей области и
  при текущей ширине окна.
  [#30](https://github.com/naghuale/tele/pull/30)
- Лента сообщений хронологическая: старые сверху, новые снизу; подгрузка старых не
  сдвигает то, что человек уже видит, а заголовок разговоя остаётся на экране при
  прокрутке.
  [#32](https://github.com/naghuale/tele/pull/32)

### Исправлено

- Ответ на `getMe` больше не приходит от другого запроса: идентификаторы запросов
  выдаёт один генератор, и предупреждение о неопределённом результате больше не
  зависит от того, кто ответил первым.
  [#61](https://github.com/naghuale/tele/pull/61)
- Чат открывается с экраном сообщений, и подгрузка старых доходит до конца истории,
  а не останавливается на первой странице, которая ничего не принесла.
  [#58](https://github.com/naghuale/tele/pull/58)
- История чата открывается: TDLib пишет большие числа строкой, и разбор страницы
  падал целиком — вместо сообщений было «Failed to load history».
  [#56](https://github.com/naghuale/tele/pull/56)
- Текст из Telegram больше не двигает курсор и не рисует ничего лишнего: управляющие
  символы и escape-последовательности из названий чатов, превью и текста сообщений не
  исполняются терминалом.
  [#56](https://github.com/naghuale/tele/pull/56)
- Ширина текста считается так, как его рисует терминал: программа спрашивает терминал
  о ширине сомнительных символов, поэтому эмодзи в названиях чатов не ломают рамки и
  переносы строк.
  [#51](https://github.com/naghuale/tele/pull/51)
- Испорченный ключ очереди больше не выдаётся за отсутствующий: к предложению начать
  очередь заново приводит только настоящее отсутствие ключа, иначе — «Run telecli
  doctor».
  [#23](https://github.com/naghuale/tele/pull/23)
- Номер телефона не спрашивается на запуске, если он уже сохранён при настройке.
  [#4](https://github.com/naghuale/tele/pull/4)
- Отказ Telegram на этапе входа (например, неверный номер) больше не оставляет
  программу ждать: авторизация заканчивается с читаемой причиной, в которой нет
  секретов.
  [#3](https://github.com/naghuale/tele/pull/3)
- API hash, введённый при настройке, сохраняется как введённый: чтение секрета больше
  не затирает его нулями, из-за чего Telegram отвечал `API_ID_INVALID`.
  [#7](https://github.com/naghuale/tele/pull/7)
- Папка данных не подменяется относительной `.telecli`, когда домашней папки нет:
  запуск заканчивается понятной ошибкой, пока не задан `data_dir`.
  [#2](https://github.com/naghuale/tele/pull/2)

### Безопасность

- TDLib не печатает подробности запросов, пока идёт приём: уровень журналирования
  понижается до того, как начнётся первый приём, а не после него — строка с `api_hash`
  больше не появляется в выводе `configure` и `tui`.
  [#5](https://github.com/naghuale/tele/pull/5)

## [v0.1.0-rc1] - 2026-09-26

Первый сбор, который можно поставить на настоящий аккаунт. Подробные заметки
выпуска — в [`RELEASE_NOTES_TEMPLATE.md`](RELEASE_NOTES_TEMPLATE.md); здесь то же
списком для человека.

### Добавлено

- `telecli configure` — настройка без ручного редактирования конфигурации: TDLib,
  приложение Telegram, аккаунт, режим доставки и хранилище; результат проверяется и
  только потом записывается.
- `telecli configure status` — безопасный статус без значений секретов,
  `telecli configure reset` — удаление конфигурации и профиля, не трогая очередь и её
  ключ.
- Профиль Telegram в macOS Keychain одним элементом: API hash и телефон не лежат в
  конфигурации, а источник выбирается целиком — смешать два источника нельзя.
- Зашифрованная очередь отправки: SQLite для метаданных, XChaCha20-Poly1305 для
  текста, ключ — в Keychain. Ошибка ключа, шифра или базы останавливает отправку;
  запасного пути «отправить напрямую» нет.
- Два явных режима отправки, `direct` и `durable`; по умолчанию `direct`.
- Сборка macOS-артефакта с native loader: релиз прерывается, если TDLib не загрузился.
- Наблюдение за работающей программой: состояние соединения, очередь, восстановление
  прерванных сообщений — без идентификаторов и текста сообщений.
- `telecli doctor` — проверка окружения и очереди.

### Исправлено

- Второй запрос параметров TDLib больше не отклоняется с `Unexpected
  setTdlibParameters`: запрос порождается один раз.

### Безопасность

- Уровень журналирования TDLib понижается до 1 до создания клиента авторизации, то
  есть до любого запроса с credential; уровни 2 и выше для production запрещены —
  на них `api_hash` попадает в вывод.
- Конфигурация пишется атомарно с правами 0600, каталоги — с правами 0700; API hash
  вводится без отображения и не передаётся аргументом командной строки.
