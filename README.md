# telecli

Терминальный клиент Telegram поверх TDLib: список чатов, переписка и
очередь отправки, которая переживает перезапуск программы.

Состояние не спрятано в одном месте: то, что человек видит в интерфейсе,
тем же лежит в очереди на диске, а что лежит в очереди — читается
командой `telecli doctor`.

## Что умеет

- список чатов с поиском `/`, счётчиком непрочитанных и последним
  сообщением;
- переписка, которая вверх подгружается постранично, имя автора в группе
  и строка состояния под названием разговора: соединение, `2 queued`,
  присутствие собеседника;
- очередь отправки на диске: сообщение, принятое Telegram, но не
  подтверждённое, не теряется при перезапуске и не отправляется дважды;
- состояние доставки под каждым исходящим сообщением — `Queued`,
  `Sending`, `Retrying`, `Sent`, `Failed`, `Delivery uncertain`,
  `Canceled`;
- если защищённая очередь не открылась, отправка останавливается, а не
  идёт в обход очереди: чаты и история видны, набранный текст остаётся,
  и уже принятые сообщения уйдут, когда очередь снова откроется;
- три тёмные темы и четыре профиля цвета терминала: True Color,
  ANSI-256, ANSI-16 и без цвета.

Что означает каждое слово в интерфейсе и что делать, когда отправка на
паузе, — в [docs/help](docs/help/README.md).

## Требования

- Go 1.27 или новее и CGO. Без CGO программа собирается, но TDLib не
  загрузится.
- TDLib 1.8.67, commit `ea97bcdd3a15523c58ddfe772b4547187cf5bbeb`,
  shared-библиотека `tdjson`: `libtdjson.dylib` на macOS,
  `libtdjson.so` на Linux.
- macOS arm64 — проверенная платформа. Linux amd64 и arm64 собираются и
  проходят тесты, но с настоящей библиотекой TDLib не проверены.
  Windows не поддерживается.

Библиотека ищется по порядку: `TELECLI_TDLIB_LIBRARY`, путь из
конфигурации, библиотека рядом с программой, затем системные места
(`/opt/homebrew/lib/libtdjson.dylib` и `/usr/local/lib/libtdjson.dylib` на
macOS, путь по умолчанию загрузчика на Linux). Путь, который задал
человек, не подменяется другим: если он не подошёл, программа скажет
об этом и остановится. Сборка с тегом `telecli_dev` добавляет путь из
дерева репозитория.

## Сборка и запуск

```
go build ./cmd/telecli
./telecli configure
./telecli doctor
./telecli tui
```

`configure` спрашивает API id, API hash и номер телефона, проверяет форму
hash (32 шестнадцатеричных символа) и кладёт hash и телефон в Keychain
под именем профиля. Сам API id секретом не считается и остаётся в файле
конфигурации. На платформе, где хранилища секретов нет, профиль не
работает: данные Telegram берутся из переменных окружения
`TELECLI_TDLIB_API_ID`, `TELECLI_TDLIB_API_HASH` и
`TELECLI_TDLIB_PHONE`. Источник ровно один за запуск — смешивать их нельзя.

Файл конфигурации ищется так: `--config`, затем `TELECLI_CONFIG`, затем
`telecli/config.toml` в системном каталоге пользователя (`~/.config` на
Linux, `~/Library/Application Support` на macOS), затем встроенные
значения по умолчанию. Данные очереди и журнал лежат в
`~/.local/share/telecli`.

Полный список команд — `telecli --help`.

## Данные и приватность

- Текст сообщения в очереди зашифрован ключом очереди. Ключ лежит в
  системном хранилище секретов — Keychain на macOS, Secret Service на
  Linux, — а не рядом с базой, поэтому потерянный ключ означает, что
  базу уже не прочитать. `telecli outbox reset` начинает новую пустую
  очередь только в этом случае, требует подтверждения словом `reset` и
  сохраняет старую базу рядом как `outbox.db.orphaned-<метка>`.
- В журнал не пишутся API hash, номера телефонов и статусы
  присутствия. Полный путь причины остаётся в журнале, а не в строке
  `Details:` на экране.
- Состояние чата не хранит ни имени, ни номера телефона, ни логина
  пользователя: магазин держит идентификатор и статус, а имя
  собеседника читается в момент отрисовки и живёт в ограниченном
  буфере. Тест печатает весь магазин и проверяет, что в нём нет ни
  одного из этих полей.

## Проверка

```
gofmt -l .
go vet ./...
go test -race -count=1 ./...
golangci-lint run --timeout 5m ./...
go mod tidy -diff
```

Эталонные снимки экрана переписываются одной командой
`go test ./internal/tui -run Snapshot -update`, и только те, чей тест
запустился.

Правило дерева: в фикстуре, в эталонном снимке и в записанном ответе
TDLib стоят только вымышленные значения. Имя, номер телефона,
идентификатор аккаунта или чата и текст настоящего сообщения в
репозиторий не попадают — его читают все.
