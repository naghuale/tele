# Отладка живой подписки

Страница о том, как узнать, что именно происходит с живым списком чатов,
когда он не ведёт себя так, как должен. Нужна редко: всё, что человек
обычно видит, описано на странице [Список чатов](chat-list.md).

## Когда это нужно

Список чатов обновляется сам: пришло сообщение в любой чат — строка
изменилась и поднялась наверх. Если этого не происходит, строка состояния
говорит, обновляется ли список вообще:

- `list does not update itself · R to reload` — живых обновлений у программы
  нет. `R` перечитывает список один раз, но сам он его не оживит: проверьте,
  что в журнале нет строки `telegram live chat list not loaded`, и
  перезапустите программу;
- строки нет — живая подписка в программе есть, и вопрос в том, на каком
  шаге она останавливается. Вот для этого страница.

## Как включить

Переменная окружения `TELECLI_DEBUG_LIVE` и путь к файлу:

```sh
TELECLI_DEBUG_LIVE=~/telecli-live.log telecli
```

Программа дописывает в файл по одной строке на каждый шаг и **ничего не
делает, когда переменная не задана**: файл не создаётся и не открывается.

Файл дописывается, а не перезаписывается, так что два запуска можно
сравнить. Права файла — `0600`.

## Что в строке

Строка состоит из времени и шага, а шаг — из пар `ключ=значение`:

```text
2026-10-02T21:40:11.013Z store.update type=updateNewMessage changed=yes err=no chat=17eb23f8
2026-10-02T21:40:11.013Z store.signal
2026-10-02T21:40:11.013Z live.wait reason=change
2026-10-02T21:40:11.013Z tui.live_changed screen=chats
2026-10-02T21:40:11.013Z tui.wait_armed
2026-10-02T21:40:11.099Z tui.repaint_due
2026-10-02T21:40:11.100Z tui.chat_list phase=before offset=0 selected=0 row=0
2026-10-02T21:40:11.100Z tui.repaint_drawn chats=20
2026-10-02T21:40:11.101Z tui.frame changed=yes
2026-10-02T21:40:11.101Z tui.chat_list phase=after offset=0 selected=0 row=0
2026-10-02T21:40:11.101Z tui.repaint scheduled=yes
```

| Шаг | Что означает |
|---|---|
| `program.start` | модель собрана; `live=yes` — за ней есть живое состояние |
| `store.update` | в живое хранилище пришло обновление TDLib; `type` — какое, `changed` — изменило ли оно хранилище, `err` — не было ли ошибки разбора, `chat` — хеш чата |
| `store.signal` | хранилище отправило сигнал об изменении |
| `live.wait` | ожидание адаптера вернулось; `reason=change` — по изменению, `reason=context` — программа закрывается |
| `tui.wait_armed` | интерфейс вооружил следующее ожидание |
| `tui.live_changed` | интерфейс получил сообщение об изменении; `screen` — `chats`, `conversation` или `auth` |
| `tui.repaint_due` | подошло время отложенной перерисовки |
| `tui.chat_list` | где было окно списка чатов до и после: `offset`, `selected`, `row` |
| `tui.repaint_drawn` | перерисовка прочитала состояние; `chats` — сколько чатов в нём |
| `tui.frame` | изменился ли текст кадра на экране |
| `tui.repaint` | запрошена ли полная перерисовка |

`type` — это `updateNewMessage`, `updateNewChat`, `updateChatLastMessage`,
`updateChatPosition`, `updateChatReadInbox` или `other`: остальной трафик
TDLib в один Bucket. `store.signal` пишется в момент отправки сигнала,
поэтому строка обновления, из-за которой он отправлен, стоит рядом — с
микросекундной разницей.

## Чего в файле нет

Ни текста сообщений, ни имён чатов и людей, ни номеров чатов: `chat` —
это короткий хеш, чтобы строки одного чата можно было сопоставить между
собой. Хеш не спрячет номер от того, у кого номер уже есть.

## Как читать файл

Одно прибывшее сообщение — это одна цепочка строк: `store.update` со
сработавшим `store.signal`, затем `live.wait reason=change`, затем
`tui.live_changed` и `tui.repaint_drawn` с `tui.frame changed=yes`.

Шаг, которого нет между двумя нашими, — это место, где изменение
остановилось:

- нет `store.update` — TDLib не прислал обновление о чате. Список
  обновляется только по тем чатам, список которых программа запросила у
  TDLib при входе;
- `store.update changed=no` и нет сигнала — обновление пришло, но ничего
  не изменило: у чата, которого нет в хранилище, или порядок не поменялся;
- `store.signal` есть, а `live.wait` нет — ожидание не вернулось;
- `live.wait` есть, а `tui.live_changed` нет — сообщение не дошло до
  интерфейса;
- `tui.repaint_drawn` есть, а `tui.frame changed=yes` нет — состояние
  прочитано, а экран выглядит так же;
- `tui.chat_list` показывает, куда уехало окно списка: строка, получившая
  сообщение, может оказаться выше окна, если курсор стоит низко.
