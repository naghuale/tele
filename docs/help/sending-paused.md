# Отправка приостановлена (Sending paused)

Эта страница объясняет сообщение telecli:

```
Sending paused
Sending is paused. Your message was not sent and is still here.
telecli could not open its secure message queue, which keeps unsent
messages safe if the app closes.
```

## Что это значит

Каждое сообщение, которое вы отправляете, telecli сначала кладёт в
защищённую очередь на вашем компьютере и только потом передаёт в Telegram.
Если программа закроется, пропадёт сеть или компьютер уснёт в этот
момент, сообщение не потеряется: при следующем запуске telecli доставит
его из очереди.

Текст сообщений в очереди зашифрован. Ключ шифрования хранится не рядом
с очередью, а в системном хранилище секретов: Keychain на macOS, Secret
Service на Linux.

Если очередь открыть не удалось, telecli **не отправляет сообщения в
обход неё**. Иначе сообщение могло бы тихо потеряться при закрытии
программы, а вы бы об этом не узнали. Поэтому отправка приостанавливается,
а всё остальное продолжает работать:

- чаты и история видны;
- набранный текст остаётся в поле ввода, его можно скопировать;
- сообщения, которые уже стояли в очереди, никуда не делись и уйдут,
  когда очередь снова откроется.

## Что делать

Запустите в терминале:

```
telecli doctor
```

Он покажет, какая из причин ниже случилась, и путь к папке данных. Под
сообщением в telecli тоже есть подсказка для конкретной причины.

### Keychain заблокирован или доступ запрещён

Подсказка: `Unlock your Keychain or allow telecli access, then restart telecli.`

**Почему.** macOS не отдал ключ очереди: связка ключей заблокирована, или
при запросе доступа было нажато «Запретить».

**Как исправить.**

1. Откройте «Связка ключей» (Keychain Access) и разблокируйте связку
   «login» (вход).
2. Перезапустите telecli. Если macOS спросит, разрешить ли telecli доступ
   к ключу, нажмите «Разрешить» или «Разрешать всегда».

Сообщения в очереди сохранены и уйдут после перезапуска.

### Ключ очереди не найден

Подсказка: `The key for your message queue is missing. Run telecli doctor for details.`

**Почему.** Очередь на диске есть, а ключа от неё в Keychain нет.
Например, запись удалили вручную, или папку данных перенесли с другого
компьютера.

**Что это значит для сообщений.** Без ключа сообщения, которые остались в
очереди, прочитать нельзя: они зашифрованы именно этим ключом. telecli не
создаёт новый ключ сам: иначе старая очередь стала бы нечитаемой навсегда,
и вы бы не узнали, что в ней что-то было.

**Как исправить.**

- Если ключ удалили по ошибке и у вас есть резервная копия связки ключей
  (Time Machine), восстановите запись `telecli-outbox` из неё и
  перезапустите telecli.
- Безопасно начать новую очередь с отказом от старой telecli пока не умеет.
  Это отдельная задача. До её выполнения не удаляйте файлы в папке данных
  вручную.

### Нет защищённого хранилища ключей

Подсказка: `This system has no secure key storage, so messages cannot be queued safely.`

**Почему.** На Linux telecli хранит ключ через Secret Service (например,
GNOME Keyring или KWallet). На сервере без графической сессии или в
контейнере его обычно нет. Хранить ключ в обычном файле telecli
отказывается: тогда шифрование ничего бы не защищало.

**Как исправить.** Запускайте telecli в сеансе, где работает Secret
Service. Например, в обычном рабочем столе, где разблокирован GNOME Keyring
или KWallet. Режим без хранилища секретов пока не поддерживается.

### Папка данных доступна другим пользователям

Подсказка: `The telecli data folder is accessible to other users. Run telecli doctor to fix it.`

**Почему.** В папке данных лежит очередь сообщений. Если у других
пользователей компьютера есть к ней хоть какой-то доступ (чтение, запись
или вход в папку), telecli её не открывает.

**Как исправить.** Закройте доступ для всех, кроме себя. Путь к папке
покажет `telecli doctor`:

```
chmod 700 "<путь к папке данных>"
```

Затем перезапустите telecli.

### Другая причина

Подсказка: `Run telecli doctor to see what went wrong.`

Причина не подошла ни под один случай выше, например файл очереди
повреждён. `telecli doctor` покажет подробности. Если они непонятны,
откройте issue в репозитории и приложите вывод `telecli doctor`. В нём
нет текста сообщений, номеров телефонов и ключей, но перед отправкой
всё равно его просмотрите.
